# 2026-09-23

## Fixes

- "Mark all as read" failed with a 404: chats and threads were sent as `POST`; the web app uses `PATCH /internal_api/chat_rooms/mark_all_as_read?only_unread=true` and `PATCH /internal_api/chat_threads/mark_all_as_read` (notifications stay `POST`). All three steps are now tried and the error names the failed ones. Verified live: all three answer `200 {"success":true}`; the old `POST` on chat rooms answers 404.
- Row actions in the "what's new" list did nothing: a private `chooser()` method shadowed Obsidian's `chooser` field on `SuggestModal`, so every action threw. Renamed; a spec guards the names.
- Counts drop immediately when items are opened, read or archived (`ActivityWatcher.adjustCounts`); the next check confirms.
- Hand cursor on every clickable element of the plugin's UI.

## 1.1.1

- First background check ran a full interval after startup instead of 3 seconds: `onLayoutReady` re-armed the fresh timer. `start()` now reports whether it started; only a running watcher is re-armed.

## Mobile and responsive UI; per-vault session

- Mobile pane: `CommunityInbox` (native what's-new inbox) replaces the "open in browser" card. The community cannot be hosted on mobile: no `<webview>`, and `www.knowii.net` sends `X-Frame-Options: SAMEORIGIN`. Decision (Sébastien): native inbox; the session stays desktop-synced, no mobile sign-in.
- Responsive: container on `.knowii-community-content`. The old `@container (max-width: 640px)` never matched: the container was `.knowii-community-body`, a sibling of the toolbar. Labels now drop at 960px (the labelled toolbar needs about 900px; it wrapped to two rows before), shortcuts fold into a "Go to" menu at 480px. Verified live: toolbar one row from 320px to 1400px.
- Touch: 40px toolbar buttons, 36px row actions, row actions always visible (`.is-mobile`, `hover: none`), keyboard hints hidden on mobile in the list and compose windows, compose fields stacked on phones.
- Settings: toolbar, last page, zoom, system notifications, status bar hidden on mobile.
- Verified live with mobile emulation plus `Platform.isDesktopApp = false`: inbox lists 76 items, no horizontal overflow at 360/390/768/1400px, filters and search on one row.
- Fix (notesSeb-e2us): the cookie partition was app-wide (`persist:knowii-community`), so opening another vault (the OSK kit) wrote the main vault's session into that vault's `data.json`. Partition is now per vault (`persist:knowii-community-<app.appId>`). The main vault's session comes back from its `data.json` into the new partition at startup (verified: signed in through `electron-session`). The old shared partition is no longer read.
