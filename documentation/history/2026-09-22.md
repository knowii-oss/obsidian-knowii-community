# 2026-09-22

## In-Obsidian notifications

- New: background watcher for community activity (direct messages, chat messages, thread replies, mentions, comments, posts, reactions, events, new members, other), with notices, system notifications, status bar counts, a ribbon badge, a "Show what's new in Knowii" list and a "Check now" command. All on by default, one switch per category.
- Data source: the community's own web endpoints (`/internal_api/...`) as the signed-in member. Circle's Headless API needs the Business plan, which is not an option for now (decision by Sébastien).
- Transports, in order: Electron session of the pane's partition, hidden webview on the same partition, stored cookies over `requestUrl` (mobile).
- The session cookies are persisted in `data.json` (decision by Sébastien); the "Hosted, not reimplemented" and "session never enters data.json" rules were removed. New rules: never sign the member back in after a sign-out in this run; notifications never block or flood.
- The pane is no longer re-rendered on non-pane settings changes (it used to reload the community on any settings write).

Verified live in Sébastien's vault: signed-in check through the Electron session (50 notifications, 30 unread items), hidden webview and stored-cookie transports, backlog notice, per-item notices, status bar, ribbon badge, list modal, settings tab.

Open: no unread direct message was available to verify a DM notice end to end (covered by unit tests on captured shapes).

## Admin menu, ribbon menu, Gmail-style list

- Admin detection from `/internal_api/pundit_users` (`current_community_member.is_admin`). Admins get an Admin menu in the pane toolbar (Dashboard `/settings/dashboard`, Audience `/settings/audience/manage`), the same entries in the ribbon menu, and two commands (hidden for non-admins via `checkCallback`).
- Right-click on the ribbon icon: latest unread items (12 max), "Show what's new (N unread)", "Check now", admin pages.
- Pane toolbar: inbox button with the unread count, opens the list.
- The list now shows recent activity, read and unread (latest 50 notifications, latest 30 conversations, unread threads and rooms), unread in bold with a dot; `is:unread` filters. Items carry `unread`; only unread ones are announced, remembered as seen and counted.
- If background checks are off, browsing the pane still triggers one check so the admin role and counts are known.

Verified live: admin role true for Sébastien, admin button and menu (Dashboard, Audience), admin commands, ribbon menu, list with 80 rows of which 30 bold (font-weight 700 vs 400).

## Whole-community watch, read and archive

- Watch the whole community (on by default, one switch per space): new posts and comments from `home_page_posts?sort=new_activity` + `post_details`, new chat messages in every chat space (unread rooms each check, the others rotating 6 per check, room uuids resolved 8 per check and cached). Only activity after the per-device watch start; own activity skipped; watch items de-duplicated against notifications; space-chat room items give way to per-message items.
- Read and archive: per item (row buttons, Mod+Enter, Alt+Enter), mark all as read (confirmed), archive read; opening an item marks it read. Community-backed for notifications, rooms and threads (endpoints and verbs taken from the web app's bundle: PATCH for per-item read and archive, POST for mark-all and thread read; CSRF from the `csrf_token` cookie). Local read/archived state and a 14-day watch log in local storage.
- Settings tab rebuilt when the known spaces change, so the per-space switches appear after the first check.

Verified live: 40 spaces and 24 chat rooms resolved; with the watch start moved back 3 days (then restored), messages from General and Wins & Celebrations with sender names and deep links; one notification marked read on Circle (inbox count 50 → 49) then archived (gone from Circle's list); list toolbar, row actions, shortcuts, ribbon entries, per-space settings.
